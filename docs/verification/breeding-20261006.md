# Native daycare scenarios / 原生寄养情景

Read-only increment after `26a2084`; version unchanged. Overall acquisition,
breeding, map access and planning coverage remains partial for all five inputs.

## Exact native entry points / 精确原生入口

| Fingerprint profile | Compatibility | Full ordinary egg receipt | Pending input width | Located receiving paths |
|---|---|---|---|---|
| Dark Phantom BW | `0x08070D4C` | `0x080708C8` | 32 bit | 2 |
| Dark Phantom DP | `0x08070D4C` | `0x080708C8` | 32 bit | 2 |
| Spanish Rocket | `0x0809ED3C` | `0x0809E8B0` | 32 bit | 0 — unknown |
| Ultimate Emerald | `0x08070D4C` | `0x080708C8` | 32 bit | 6 |
| Mercury 1.2 | `0x0804654C` | `0x080460D4` | 16 bit | 0 — unknown |

Addresses, layouts and verified dispatch identities are adapter configuration.
All names, stats, learnsets, inheritance/item tables and constructor decisions
come from the current ROM. The complete routine executes in disposable RAM,
including patched branches and native getters/setters/RNG. No function is replaced
and no ROM/SAV byte is written. Receiving paths are bounded script references;
they are not a claim about NPC access, party space or a pending egg.

The native routines differ materially: Mercury compares national identities in
ordinary same-species compatibility and has an extended constructor; Ultimate
changes the helper signature/parent selection; Dark Phantom changes some baby
selection/incense paths. The implementation does not replace these with an
official evolution-family formula or an extracted baby/item catalog.

## User workflow / 使用流程

Open a Pokémon acquisition query → expand **Native daycare egg preview** →
choose two stored individuals or simulated parents → preview ordinary egg receipt
→ follow the simulated offspring/move links or a located receiving NPC → inspect
map tile, exterior approaches and return to the query. Shared map NPC details
also explain the service and parsed conditions. Both languages use the same UI.

Stored parents keep all original 80-byte individual records, including moves,
items, IVs, OT and history. Two references to the same storage location are
rejected; eggs, invalid identities and corrupt represented records are rejected.
A simulated parent is explicitly level 5, zero IVs, no moves; simulated pair OTs
are distinct. Seed and pending personality are reproducible scenario inputs,
not a forecast of the next real egg. When present, persistent SAV blocks supply
owner/script context to the isolated scenario; the actual party is not replaced.
Only ordinary logical persistent blocks are restored here; live RAM and complete
extension-dependent context are not claimed.

The native base compatibility result is **not** an egg-production probability.
Incense, child selection, moves and individual fields reflect this specific
receipt scenario. Complete inheritance coverage, charm/production rates, next
pending personality, live daycare state, hatching, access and full form behavior
remain separate work. A native failure does not silently return a vanilla result.

Rocket and Mercury retain ordinary receiving routines, but this parser currently
finds no located service. The UI explicitly says this is unknown; missing
references do not establish absence. Legacy code and unreferenced records are
not promoted to obtainable eggs. Breeding candidates remain candidates, and
collection planning does not treat a simulated child as captured or owned.

## GBA CPU correction / GBA CPU 修正

Independent full-record comparison exposed an existing sandbox issue:
`armv4t_emu` 0.1.3 discards the low address bit for Thumb halfword loads. On GBA,
odd LDRH rotates the aligned halfword in a **32-bit** register; odd LDRSH
sign-extends the addressed byte. A current Ultimate inheritance helper reaches
an odd ROM address, so the previous sandbox returned a different move set.

`Sandbox` now corrects only odd Thumb immediate/register LDRH and register LDRSH.
It preserves flags, advances PC once, and keeps all function control flow and
aligned accesses. This is shared CPU behavior, with no ROM-name/PC-specific
branch. ARM-mode halfword behavior and a complete CPU conformance suite are not
claimed by these tests.

The first Ultimate test previously returned a legacy helper count of 12;
mGBA returns 20. After the correction the full 100-byte generated record and
RNG state agree. The purpose is to reproduce current ROM execution, including
legacy helpers, not to assert that every game breeding rule is bug-free.
Primary implementation orientation: [mGBA memory loads](https://github.com/mgba-emu/mgba/blob/0.10.5/src/gba/memory.c).

## Evidence and reproduction / 验证与复现

`scripts/verify_breeding.py` and `scripts/native/breeding_probe.c` expose a
read-only ROM, RAM-only fixture writes and bounded complete native calls. They
have no battery import/export or cheat/ROM-write API. Exact input hashes and
native ROM-memory preservation are checked; no user SAV is opened by the oracle.
Probe JSON, native libraries and genuine game files stay private.

- Five exact fingerprints: 42 scenarios each, **210 compatibility/receipt cases**.
- **171 accepted-pair native constructions**, compared as complete 100-byte
  individual records, compatibility values and final RNG state.
- Cases cover parent order, same/different OT, same sex, Ditto pairs, genderless
  pairs, babies, selected incense cases, three seed/personality inputs and the
  actual simulated-parent request bytes.
- **120 mGBA halfword microcases**, checking aligned/odd immediate/register loads
  and signed extension with distinct byte patterns. Public CPU fixtures also
  verify flag/PC preservation and aligned delegation.
- Public five-adapter fixtures retain script guards/NPC tiles, reject altered
  native dispatch, and preserve SAV/parent history. Browser fixture covers stored
  selection, offspring/map/back, bilingual labels, IV display and no edit calls.
- All **107 public core tests passed**, with 27 opt-in tests excluded from the
  ordinary run. Five-fingerprint acquisition/collection, map navigation,
  resource conditions, tutor selection, NPC trade, pickup and qualified NPC
  reward regressions passed, alongside adapter/storage checks.
- **1,484 Mercury ordinary zero-context trainer scenarios** retain every
  previously independently verified individual field after the shared CPU
  correction. This does not establish full live-battle or extension context.

With the existing private `GEN3_ROM_*` variables and a built mGBA 0.10.5:

```sh
cc -O2 -shared -fPIC -DM_CORE_GBA -DM_CORE_GB -DUSE_DEBUGGERS \
  -I"$MGBA_SOURCE/include" -I"$MGBA_BUILD/include" \
  scripts/native/breeding_probe.c "$MGBA_LIBRARY" \
  -Wl,-rpath,"$MGBA_BUILD" -o /private/breeding-probe.dylib
python3 scripts/verify_breeding.py --mgba-probe /private/breeding-probe.dylib \
  --output /private/breeding.json
GEN3_BREEDING_PROBES=/private/breeding.json cargo test -p gen3-core \
  local_breeding_matches -- --ignored --nocapture
cargo test -p gen3-core
uv run --with playwright python scripts/test_breeding_ui.py
```

Use a Python matching the native library architecture. Unicorn-only output is
available for research but is not accepted as exact GBA halfword evidence.
