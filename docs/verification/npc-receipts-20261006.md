# NPC receipt protocols / NPC 领取协议

Increment over `916d270`; development version unchanged. This verifies a bounded
reward protocol, not complete NPC/story coverage. Input fingerprints are the five
registered entries in [the capability matrix](../capability-matrix.md).

## Runtime method / 实时方法

The broad item-script walker still returns ROM-backed gifts, item balls, shops,
guards and unresolved offsets. A separate pass uses the **same decoder/control
flow** to qualify receipts; its limits do not truncate the broad catalog. No NPC
names, reward lists or task catalog are embedded.

A gift can carry `ItemReward.receipt` only when all of these hold:

1. Its path checks a flag **unset** before awarding the item. Object visibility
   is not used as this guard's substitute.
2. Its item and positive quantity are resolved from the current script.
3. The exact adapter's native standard gift/add-item result is a boolean in
   `VAR_RESULT` (`0x800D`). The proof explores failure and success independently,
   including calls, copied results and conditional returns.
4. Every completed success path sets that flag **after** the award and leaves it
   set. Failure, rejection and alternate reward paths must not leave it set.
   A shared flag cannot prove that both alternative items were received.
5. No unsupported command, caller native effect, unknown standard-script effect,
   invalid pointer, cycle/merged path or traversal bound prevents a complete proof.

The proof contains the flag, root, award instruction and successful setter
addresses. It is per reward, separate from `MapMarker.flag` and the independently
verified item-ball `receipt_flag`. The standard gift's presentation body is a
verified engine rule, not an arbitrary NPC script whitelist.

Normal parsing does not assume a result for unresolved native/PC rewards. The
SAV query reads only the previously native-verified persistent ranges. A flag
outside these ranges stays unknown. Qualified flag-set gifts are collected;
qualified unset gifts still require known prerequisites. Unqualified gift/PC
receipts stay **undetermined**, even if the NPC is hidden or the bag lacks an item.

## Independent native comparison / 独立原生对照

`scripts/verify_npc_receipts.py` reads the current ROM and CLI world query. It
executes the native command dispatch, variable comparisons, calls/returns,
standard-script selection and FlagSet/Get in isolated synthetic RAM. Every
qualified record runs four cases: receipt unset/set × bag insertion failure/success.
The set-receipt cases must skip the award; failure must not newly set its flag;
success must set it. ROM memory and on-disk input hashes are checked unchanged.
No SAV is opened, edited or generated by this verifier.

Bag insertion returns are **injected**. Text, waits, music and presentation
specials are bypassed. Mercury's native `0xD4` item-name formatting and
`0x1D5DEB0`/`0x1D5DEE0` item-icon sprite helpers are presentation, not receipt
selection. Its add-item bookkeeping helper `0x9A824` is bypassed in synthetic
context. This proves the following native control-flow cases, not full gameplay,
real inventory capacity or a complete field interaction replay.

## Query workflow and regression / 查询流程与回归

- The source query forwards per-reward evidence and the SAV receipt status.
  Clicking its map focuses the target tile; map details retain the NPC and item
  link, with flag/root/setter evidence inside expandable technical details.
- The regional collection planner excludes collected gifts using receipt state;
  ROM reference retains all events. Unknown rewards remain opt-in. Acquisition,
  planning and standalone HTML explain qualified/unknown receipts in both languages.
- Public branch fixtures exercise successful/failed awards, copied results,
  subroutine returns, direct add-item, unconditional/cleared flags, alternative
  awards sharing a flag, dynamic quantity, unknown/native commands and cycles.
  Query/planning fixtures for all five adapters verify that visibility and bag
  contents do not replace the actual per-reward receipt and that SAV bytes remain
  unchanged.
- Native NPC parity, prior 1,956 ordinary pickup parity rows, and `local_query_`
  acquisition/navigation regressions passed across all five precise ROMs. Mercury
  planning also checks an actual private SAV copy for no changes.
- Public core/CLI suite: **93 passed, 21 opt-in ignored**. TypeScript/Vite,
  formatting, version consistency and diff checks passed. Clippy passed with
  only the six previously documented baseline exclusions; strict-clean status
  is not claimed. The existing >500 kB frontend chunk warning remains.
- `scripts/test_npc_receipt_ui.py` passed source → NPC tile → evidence → return →
  planner → bilingual HTML, with no save mutation/export calls.
  `scripts/test_query_collection_ui.py` passed prior map/entrance/return, HTML
  escaping and compact-window behavior.

Reproduce with private exact ROM paths in `GEN3_ROM_BW`, `GEN3_ROM_DP`,
`GEN3_ROM_ROCKET`, `GEN3_ROM_ULTIMATE`, `GEN3_ROM_MERCURY12`:

```sh
cargo build -p gen3-cli --locked
uv run --with unicorn python scripts/verify_npc_receipts.py > /private/native-npc.json
GEN3_NPC_PROBES=/private/native-npc.json cargo test -p gen3-core local_npc_receipts -- --ignored --nocapture
cargo test -p gen3-core -p gen3-cli --locked
cargo test -p gen3-core local_query -- --ignored --nocapture
# With Vite and Chrome available:
uv run --with playwright python scripts/test_npc_receipt_ui.py
uv run --with playwright python scripts/test_query_collection_ui.py
```

## Remaining boundaries / 剩余边界

Receipts are **script-local evidence**. Whole-game flag initialization and reset
writers, daily/weekly refresh, current map reachability, active replacement
layouts, full quest dependency graphs, alternative native rewards and most
Mercury custom NPC commands remain unverified. The proof does not establish a
permanent once-only reward. Fixed item-ball and hidden-item protocols keep their
own rules; this increment does not apply one ROM's flags to another.

There is no new edited-SAV emulator re-save claim in this read-only increment.
The previously delivered local app remains at its packaged commit; these changes
are not implicitly packaged or published.

规划和中英文 HTML 共用；背包道具用掉不改变已经记录的领取状态，NPC 消失不代替
领奖标记。本轮不写存档／ROM，不宣称全局最短路线，不打包或发布。
